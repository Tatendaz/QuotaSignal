# Feature: Supply-chain and CI hardening

**Branch:** security/hardening-2026-10-25
**Date:** 2026-10-25

## Summary

Slows down dependency updates and adds a workflow security check. App code is unchanged.

## Motivation

Malware this month shipped as new versions of trusted packages. A 7-day wait before a version update opens gives the registries time to pull a bad release.

## What changed

- `.github/dependabot.yml`: both ecosystems (pip, github-actions) now run monthly with `cooldown: default-days: 7` and `open-pull-requests-limit: 3`. The existing patch/minor group is kept. Security updates ignore the cooldown.
- `.coderabbit.yaml` (new): `reviews.auto_review.ignore_usernames: ["dependabot[bot]"]`, so Dependabot PRs do not spend CodeRabbit review budget.
- `.github/workflows/zizmor.yml` (new): runs `zizmor` 1.31.1 on `.github/workflows` for every push to `main` and every PR. High findings fail the job.
- `.github/workflows/dependabot-auto-merge.yml`: the top-level token is now `contents: read`. The write scopes moved to the one job that merges.

## Notes

- No pip cooldown: pip has no config key for a minimum release age. uv is not used here.
- There is no lockfile, so CI installs from version ranges. A lockfile with hashes is the next step if releases need exact builds.
- No gitleaks job: the repo is public, so GitHub secret scanning and push protection are on.
